# android — GaussX 비콘 (헬멧 비콘 · 구역 수신기 · 레이더)

> ⚠️ 잠정 (10/18 · 레이더 10/20) — 비콘 구역은 팀 합의 전 기능이다. API · 판정 값: [`docs/api.md`](../docs/api.md) '비콘 구역 · 레이더'

앱 하나로 두 역할을 한다. 폰마다 같은 앱을 깔고 역할만 다르게 고른다.

| 역할 | 하는 일 | 백엔드 연결 |
|---|---|---|
| 헬멧 비콘 (작업자 폰) | iBeacon 광고 `UUID · major · minor` (약 0.1초 간격, 연결 불가 광고) | 없음 |
| 수신기 (구역에 두는 폰) | 같은 UUID 의 비콘을 계속 스캔 → 1초마다 `POST /api/gateway` → 응답의 레이더를 화면에 | `http://노트북IP:3001` |

안 · 밖 판정과 위치 계산은 백엔드가 한다 (두 수신기의 보고가 다 모이는 곳). 앱은 들은 값을 거르지 않고 그대로 보낸다.
폰은 광고할 때 MAC 주소가 수시로 바뀌어서, 비콘은 `uuid:major:minor` 로 찾는다 — 시중 헬멧 비콘(iBeacon)도 같은 수신기로 들을 수 있다.

## 레이더 (수신기 화면)

| 수신기 | 보이는 것 |
|---|---|
| 1대 | 헬멧까지 **거리만** (그 거리쯤 어딘가 — 점선 고리) |
| **2대** | 헬멧 **위치** = 방향 + 거리 (점 + 오차 원). 다른 수신기 · 구역 사각형도 함께 |

같은 위치가 웹 **관제(`/control`) · 시연(`/demo`) 평면도**에도 나온다 (`/api/state` 의 `presence[].position`, 0.5초마다).
위치를 모르고 구역 안인 것만 알면(수신기 한 대) 그 구역 오른쪽 위에 '단말 n번 (구역 안)'.

- 가운데 = 이 수신기, **위 = 앞(구역 쪽)**, 옆 = 다른 수신기 쪽. 거리는 실제 비율로, 범위(2 · 3 · 5 · 10 m …)는 저절로 맞춘다
- 아래 글: `단말 1번  약 1.9 m · 오른쪽 앞 · 가까워지는 중 / Z1 안 · 수신기 2대가 들음`
- 거리는 신호 세기로 어림잡은 값이라 실내에서 ±50% 정도 틀린다 → **1m 보정**: 헬멧을 그 수신기 1m 앞에 두고 버튼
  (길게 누르면 지움). 보정 값은 백엔드에 저장되고, 웹 관리자 화면 '수신기 배치'에서도 보고 고칠 수 있다
- 위치는 두 거리 원이 만나는 두 점 중 **구역 쪽**을 고른다 → 두 수신기는 구역 한쪽 끝에 나란히, 구역을 바라보게 둔다
- 수신기 하나로는 방향을 알 수 없다 (안테나 하나는 세기만 잰다). 더 정확히 하려면 수신기 3대 이상(로드맵)이나 UWB 폰

## 빌드 · 설치

요구: Android Studio (내장 JDK 21) · Android SDK 35. 폰: 안드로이드 8.0(API 26) 이상 · 블루투스 LE (비콘 역할은 BLE 광고를 지원하는 폰)

```bash
cd android
./gradlew assembleDebug        # → app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # iBeacon 바이트 · 레이더 계산 단위 테스트
```

- `JAVA_HOME` 이 없으면 Android Studio 의 `jbr` 를 쓴다 (Windows: `C:\Program Files\Android\Android Studio\jbr`)
- SDK 위치: `local.properties` 의 `sdk.dir` (커밋하지 않는다) 또는 환경 변수 `ANDROID_HOME`
- 설치: 폰을 USB 디버깅으로 연결하고 `adb install -r app/build/outputs/apk/debug/app-debug.apk`,
  또는 APK 파일을 폰에 옮겨 설치 (출처를 알 수 없는 앱 허용)

## 시연 (폰 세 대: 헬멧 1 + 수신기 2)

1. 노트북: 백엔드 켜기 `cd backend` → `npm run dev` (Windows PowerShell 5.1 은 `&&` 를 못 쓴다) → 콘솔에 찍히는 노트북 IP 확인. 폰과 노트북은 같은 와이파이
   - Windows 방화벽 창이 뜨면 '개인 네트워크' 허용 (안 뜨는데 연결이 안 되면 Node.js 인바운드 3001 허용)
2. 수신기 두 대 놓기: 구역 한쪽 끝에 **2m 간격**으로 나란히, 폰 위쪽이 구역을 향하게 (개발용 씬 `gw-01` 왼쪽 · `gw-02` 오른쪽)
   - 놓은 자리는 웹 관리자 화면 **수신기 배치**(`/admin/receivers`)에서 실제와 같게 맞춘다 — 수신기를 고르고 평면도를 누르거나 x · y(m)를 넣고 저장.
     화면의 '수신기 사이 거리'가 줄자로 잰 거리와 같아야 한다 (바로 쓰고, 백엔드를 다시 켜도 남는다)
3. 폰 B (수신기 1): 역할 '수신기' · 백엔드 주소 `http://노트북IP:3001` · 수신기 id `gw-01` → 시작.
   폰 C (수신기 2): 같은데 수신기 id `gw-02`
   - 권한(근처 기기 · 정확한 위치 · 알림)을 허용하고 위치(GPS)를 켠다 — 안드로이드는 위치가 켜져 있어야 비콘 스캔 결과를 준다. 위치는 기록하지 않는다
4. 폰 A (헬멧 비콘): 역할 '헬멧 비콘' · major 1 · minor 1 (= 단말 1번) → 시작 → '광고 중'
5. 1m 보정: A 를 B 1m 앞에 두고 B 에서 '1m 보정', C 도 같이
6. A 를 들고 구역 안을 움직이면 B · C 레이더의 점이 따라온다. 백엔드에서 보기: `http://localhost:3001/api/radar?gateway=gw-01` · `/api/locate`
7. 쓰러짐: A 가 1구역 안일 때 SOS → 알림 구역 = Z1 · `zoneSource: "beacon"` (이력: "쓰러짐 · Z1 (비콘)")
   - 차이가 보이는 시연: A 를 **단말 2번**(major 1 · minor 2)으로 — 데모 데이터에서 단말 2번은 2구역 작업 중이라,
     비콘이 없으면 Z2, 1구역 수신기 옆에 있으면 **Z1 로 로봇이 간다** (실제로 있는 곳)

폰이 두 대뿐이면 헬멧 1 + 수신기 1 — 구역 안/밖과 거리만 나온다.
폰 없이 관제 화면만 시험하려면 백엔드에서 `npm run sim:gateways` (수신기 두 대 흉내 — 실제 수신기 폰과 같이 켜지 않는다).

## 현장 보정

- 구역 안/밖 문턱은 demo.json 의 `locate` (기본: -70 dBm 보다 세면 들어옴, -76 보다 약하면 나감, 2초 유지)
- 수신기를 구역에 고정하고 헬멧을 들고 구역 경계에 서서 `/api/locate` 의 `median` 을 본다 → 그 값을 `enter_dbm` 근처로
- 폰마다 세기가 다르다. 비콘 폰의 '광고 세기'(기본 '세게')와 기종을 정한 뒤에 잰다
- 거리가 계속 짧거나 길게 나오면 1m 보정을 다시, 그래도 안 맞으면 `locate.path_loss_n` (실내 2.5~3.5)
- 수신기 폰은 충전기에 꽂아 둔다. 동작 중에는 앱이 화면을 켜 둔다

## 문제 해결

| 증상 | 확인 |
|---|---|
| 수신기에 '들리는 비콘이 없어요' | A 에서 시작했는지 · 모든 폰의 UUID 가 같은지 · 수신기 폰의 위치(GPS) · 블루투스 |
| '백엔드에 보내지 못했어요' | 같은 와이파이 · 주소(IP:3001) · 백엔드가 켜져 있는지 · 노트북 방화벽 |
| '등록되지 않은 수신기예요' | 수신기 id 가 demo.json `gateways[].id` 와 같은지 |
| '백엔드에 등록 안 된 비콘' | A 의 major · minor 가 demo.json `devices[].beacon_id` 와 맞는지 |
| 레이더에 '방향 모름'만 | 다른 수신기가 꺼졌거나(회색 '꺼짐') 그 수신기에 안 들림 → 두 수신기 모두 시작했는지 · 거리 |
| 점이 구역 반대쪽(뒤)에 | 위치는 늘 구역 쪽으로 고른다 → 수신기 두 대가 구역 한쪽 끝에 나란히 있는지, `world` 가 실제 자리와 맞는지 |
| 화면을 끄면 멈춘다 (일부 제조사) | 설정 → 배터리 → 앱 → GaussX 비콘 → '제한 없음' (배터리 최적화 끄기) |
| 비콘 역할에서 'BLE 광고를 지원하지 않아요' | 그 폰은 수신기로 쓰고, 다른 폰을 비콘으로 |

## 확인한 것

에뮬레이터 두 대(안드로이드 16, 가상 블루투스)로 확인했다.
- 10/18: 광고 → 스캔 → 1초 보고 → 백엔드 판정 '안 (Z1)' → SOS 알림 구역 출처 '비콘', 비콘을 멈추면 4초 뒤 '밖' · 6초 뒤 '알 수 없음',
  두 폰 화면을 끈 채 1분 유지, 블루투스를 껐다 켜면 비콘 · 수신기 모두 자동 복구, 수신기 id 오타 · 등록 안 된 비콘 · 백엔드 꺼짐 안내
- 10/20: 수신기 2 를 보고 흉내(스크립트)로 붙여 레이더 — 헬멧이 오른쪽 앞 → 앞 → 왼쪽 앞으로 움직이는 것, 수신기 2 를 끄면 '거리만',
  1m 보정 · 지우기, '가까워지는 중'

**실제 폰에서는 아직 확인하지 않았다** — 에뮬레이터의 RSSI 는 -8 dBm 으로 고정이라 거리 · 방향 정확도와 문턱 보정은 실제 폰으로 해야 한다.

## 구조

```
android/app/src/main/java/team/gaussx/beacon/
├── MainActivity.kt       역할 · 설정 · 시작/멈추기 · 상태 · 레이더 · 1m 보정 (권한 → 블루투스 → 위치 순서로 안내)
├── AdvertiserService.kt  헬멧 비콘: iBeacon 광고 (포그라운드 서비스 · 블루투스를 껐다 켜면 다시 광고)
├── ReceiverService.kt    수신기: UUID 필터 스캔 → 1초마다 보고 · 20분마다 스캔 재시작 (30분 넘으면 안드로이드가 약하게 바꾼다)
├── RadarView.kt          레이더 그리기 (초당 30번, 1초마다 오는 위치를 부드럽게 따라간다)
├── RadarState.kt         보고 응답의 레이더 (이 수신기 기준 m) · 가까워지는 중 비교
├── RadarMath.kt          범위 · 고리 · 방향 말 (단위 테스트)
├── IBeacon.kt            iBeacon 바이트 (회사 id 0x004C · 23바이트) ↔ "uuid:major:minor"
└── Http.kt · Settings.kt · Status.kt · Foreground.kt
```

AndroidX 없이 플랫폼 API 만 쓴다 — AGP 8.9.1 · Kotlin 2.1.0 · Gradle 8.14.3 · compileSdk/targetSdk 35 · minSdk 26.
